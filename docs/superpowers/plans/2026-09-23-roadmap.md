# Diamond Vending — Implementation Roadmap

**Spec:** [`docs/superpowers/specs/2026-09-23-diamond-vending-design.md`](../specs/2026-09-23-diamond-vending-design.md)

The spec is one mod, but most of it depends on exact Minecraft/loader APIs for two game versions
(1.21.1 and 26.1.2). Writing every task's code up front would mean guessing API signatures.
Instead the work is split into **six plans, each producing working, tested software**. Plan 1
was written in full first. Each later plan is written **after the previous one merges**, when the
decompiled Minecraft sources for both versions are on disk and every signature can be checked.

| Plan | Delivers | Testable result | Status |
|---|---|---|---|
| **1 — Foundation** ([plan](2026-09-23-plan-1-foundation.md)) | JDK + Stonecutter project for {1.21.1, 26.1.2} × {Fabric, NeoForge}; mod entrypoints/metadata; CI + Dependabot; pure-Java core logic: click regions (`MachineLayout`), purchase decisions (`PurchaseRules`), problem detection (`MachineProblems`) | 4 jars build in CI; core unit tests green | Done |
| **2 — The machine** ([plan](2026-09-23-plan-2-the-machine.md)) | Loader `Registrar` abstraction + registration; 2×2 multiblock block (facing/half/side/color states, light 6, blast 1200, no pistons, wither/dragon immune); master block entity with owner; placement checks; break-all; owner/admin-only breaking & dyeing; machine item carrying color; art generator for models/textures/icon; machine recipe; GameTest harness on all 4 targets | Place, dye, and break a protected machine in-game; GameTests green | Done |
| **3 — Buying** ([plan](2026-09-23-plan-3-buying.md)) | Server side of buying: currency tag + money text; machine contents (12 selections, stock, cash box, tray, per-player credit, infinite flag) saved and synced; front-face click routing via `MachineLayout`; pickup tray; coin slot credit + coin return; purchases via `PurchaseRules`; problems via `MachineProblems`; per-click action-bar messages; lang-completeness test; vanilla sounds; contents spill on break | Stock a machine with `/data` and buy from it; GameTests green | Done |
| **4 — Seeing it** ([plan](2026-09-23-plan-4-seeing-it.md)) | Client side: block entity renderer for shelf items, price tags, LED display (green status, red scrolling problems), blinking lamp and tray contents; display flashes and the drop animation via block events; hover HUD | Everything visible and correct in a dev client on all 4 jars | Done |
| **5 — Running a shop** | Tabbed setup screen (Selections, Stock, Cash Box, Admin) with ghost slots, quantity/price editing, withdraw, problem banner and tab "!"; validated payloads; owner sneak-with-item hint; infinite toggle (requires empty stock/cash); currency slot + currency resolution; datapack catalogs (reload listener, codec, example catalog, `docs/catalogs.md`); setup kept on the item; infinite kept only for admin placers | Full owner and admin flows in-game; GameTests green | Not written |
| **6 — Manual, polish & v1.0** | "New Franchise Owner" written-book manual covering every rule; manual recipe; art polish; manual QA checklist run on all 4 jars + a dedicated server; CHANGELOG; v1.0.0 GitHub release with jars | Release published to the repo | Not written |

Plan 3 was originally "Buying" with the client rendering included; it was split so each half has
its own test cycle — the server half is covered by GameTests, the client half needs a dev client.
The owner sneak-with-item hint moved to "Running a shop" because it points at the setup screen.

Each plan runs on its own branch (`plan-N/<name>`), merges via PR after CI is green, and closes
with a short entry in `CHANGELOG.md`.
